## Technical Innovation

### The Key Insight

Auth0's OAuth2/OIDC flow with PortSwigger returns an HTML form on `/signin-oidc` endpoint. Traditionally, this requires browser automation because:
- Browsers auto-submit forms via JavaScript
- Complex JavaScript might manipulate form fields
- Session management handled by browser

**Our Solution:** Parse the form HTML and submit it via HTTP POST, eliminating browser overhead entirely.

### Why This Works

1. Form data is **static HTML** (not generated by JavaScript)
2. All needed data is in **hidden input fields**
3. Form submission is **standard HTTP POST**
4. Redirects are **standard HTTP 302 responses**
5. Session maintained via **HTTP cookies**

### Performance Impact

| Metric | Browser (Playwright) | HTTP Parsing |
|--------|-------------------|--------------|
| Per Account | 5-15 seconds | 1-3 seconds |
| Memory | ~200MB per browser | ~5MB total |
| Concurrency | 1-2 browsers | 50+ requests |
| Processing Time (217 accts) | 2-3 hours | 30-60 minutes |
| Cloud Compatible | No browser needed | Yes ✓ |

## OAuth2/OIDC Flow Implemented

```
1. GET /authorize endpoint
   ↓ Extract state parameter
   
2. POST /u/login with credentials
   ↓ Server returns 302 redirect
   
3. Follow OAuth redirect chain
   ↓ Multiple 302 responses
   
4. GET /signin-oidc endpoint
   ↓ Returns HTML with auto-submit form
   
5. PARSE FORM with cheerio
   ↓ Extract form action and all fields
   
6. POST form data
   ↓ Form submission completes OAuth
   
7. Follow post-form redirects
   ↓ Session created on server
   
8. GET /users/youraccount/licenses
   ↓ Authenticated access to subscription page
   
9. EXTRACT PLAN from HTML
   ↓ Categorize as Free/Professional/Team/Enterprise/Community
```
